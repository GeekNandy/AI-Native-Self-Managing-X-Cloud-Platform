# Material 3 engineering workspace

The browser client covers environment proposals, repository repair, state comparison, evaluations and the durable audit journal. All plans, patches, outcomes and history come from the authenticated API.

The interface uses locally served **Roboto**, **Google Material Symbols**, and light/dark color roles generated by **Material Color Utilities 0.3.0**. Native HTML forms, buttons, dialogs and tables preserve browser behavior. The app loads no CDN scripts or remote fonts and retains `script-src 'self'; style-src 'self'`. Full licenses, upstream revision and the font checksum are in `src/main/resources/static/assets/NOTICE.txt`.

Use **Ctrl K** / **⌘ K** to navigate pages. Review tabs support arrow keys, Home and End. A skip link and selected navigation state support keyboard access. Mobile navigation keeps five destinations available; theme choice persists independently of the tab credential.

Environment name/state filters, evaluation history/result selection, audit type/text filters and matching-event exports, and repository run filters help inspect real evidence. Patch lines show file headers, additions, removals and hunks without interpreting source as HTML. The connected role is visible; agent credentials expose inspection and proposals while operator controls remain disabled. The server independently enforces every access boundary.

The packaged app needs no Node runtime or frontend build step. To edit theme generation, run `npm ci`, `npm run build:theme`, then commit the generated CSS. `npm run check` checks the JavaScript and rejects stale theme tokens. Maven packages the committed local assets.

Google's [Material Web component library is in maintenance mode](https://m3.material.io/develop/web). This implementation uses the independent open source [color utilities](https://github.com/material-foundation/material-color-utilities), [symbols](https://developers.google.com/fonts/docs/material_symbols) and native controls. It is a custom Material 3 interface and uses no private Google product code.

## Verification

The browser suite exercises all five pages at 320, 390, 768, 1024 and 1440 pixels in both themes. It checks page/tabpanel focus, tab-scoped access, role restrictions, actual API history and exports, CSP/local assets, and hosted Basic authentication. Axe checks WCAG 2 A/AA, 2.1 AA and 2.2 AA rules across eleven page/dialog states. These automated checks supplement the retained desktop/mobile screenshots; they do not constitute a complete manual accessibility audit.
